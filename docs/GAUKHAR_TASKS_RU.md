# Задачи Zhaulybaeva Gaukhar

Ответственность по отчёту: выбор данных и accession review; метаданные; QC коротких и длинных чтений; выравнивание и downsampling; интерпретация покрытия и качества выравнивания.

## Что проверять самостоятельно

1. Откройте `docs/SCIENTIFIC_SOURCES.md` и accession table отчёта. Сверьте Illumina `SRR1030394`, Nanopore `SRR33602302` и reference `U00096.3` с указанными архивами. Объясните, почему одинаковое имя MG1655 при разных BioSamples не даёт контролируемого сравнения платформ.
2. Откройте `docs/ALIGNMENT_METHOD.md`. Разберите отличия QC для коротких и длинных чтений, сохранение пар, CIGAR coverage и фильтр MAPQ. Найдите соответствующие условия в `pipeline.py`.
3. В полной локальной папке проекта запустите **CHECK_GAUKHAR.cmd**. Это реальные тесты `tests/test_pipeline.py`; журнал сохраняется в `results/reviews/gaukhar_pipeline_tests.txt`. Если Python не найден или тесты не прошли, укажите ошибку и исправьте её перед утверждением об успешной проверке.
4. Откройте `results/qc_alignment_comparison.tsv` и `results/saturation.json`. Найдите retained molecules, mapping rate, широту покрытия и plateau отдельно для Illumina и Nanopore. Напишите своими словами, почему широта покрытия падает при downsampling, а mapping rate остаётся почти постоянным.
5. Проверьте `results/metadata_summary.json` и provenance. В своей заметке объясните, что означают ограничение выборки, archive release year и library strategy; почему подсчёт запусков не равен рыночной доле технологии.
6. Если требуется собственное воспроизведение, установите Node.js и в полной папке выполните `python run_experiment.py`. Это маленький реальный пример. Для повторения большого эксперимента предусмотрен `--pilot`, описанный в README; он требует скачивания больших входных данных. Укажите, какой режим вы действительно запускали.

## Что добавить от своего аккаунта после выполнения

На GitHub нажмите **Add file → Upload files**, добавьте только фактически полученный журнал, сохранив путь `results/reviews/`. Затем **Add file → Create new file**, имя `docs/reviews/gaukhar_review.md`.

Заполните заметку своими результатами:

- Дата проверки и точная команда/кнопка запуска.
- Фактически прошедшие тесты или найденная ошибка.
- Какие accessions, данные и условия фильтрации были проверены.
- Ваша интерпретация downsampling и ограничений метаданных.
- Какие содержательные исправления вы сделали, если нашли проблему.
- Ссылка на соответствующий commit или pull request.

Не копируйте заранее написанное утверждение об успешном запуске. Первоначальная загрузка своей части описывается сообщением **Upload data and coverage analysis components**. Запись проверки можно назвать **Document pipeline verification**, когда проверка действительно выполнена.

Обе части проекта нужны для полного воспроизведения. Загрузка файлов и техническая интерпретация являются разными действиями; помощь AI раскрыта в `AI_DISCLOSURE.md`.
